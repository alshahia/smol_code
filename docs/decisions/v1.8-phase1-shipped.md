### Decisions made (the ones not in §6.3)

1. **Backward-compatible project config migration (Q4 confirmed option c):** `Settings.projects` reads both `SMOLCODE_PROJECTS=proj=<absolute_path>` (explicit) and `SMOLCODE_PROJECTS=proj` (bare name → auto-create `<workspace>/<name>`). Legacy `workspace` becomes the implicit "default" project when no projects are configured.
2. **Sessions are scoped to projects, not global:** `GET /api/sessions?project=foo` returns the project's session list. Bare `GET /api/sessions` falls back to the workspace (legacy behaviour). Allows future cross-project session search without forcing it now.
3. **Atomic session-file writes:** `create_session_file` writes to `meta.json.tmp` then `os.replace()` — prevents partial meta.json on crash.
4. **Project switcher localStorage persistence:** `smolcode.web.activeProject` is restored on mount via `localStorage.getItem('smolcode.activeProject')`. Same pattern as `smolcode.lastProvider` (decision 0014 §12.4).
5. **SessionsPane placement:** lives in the left pane between Tasks and History, behind a tab toggle (`activeTab: 'task' | 'sessions' | 'history' | 'uploads' | 'allowlist'`).

## Known limitations

- **Bare `GET /api/sessions` (no `?project=`)** returns all sessions across all projects. Acceptable today (low cardinality) but worth a followup if cross-project UX needs it.
- **Sessions are NOT migrated on project rename/delete** — old sessions under the old project path become orphaned. Recommended for Phase 3 (audit + dashboard).
- **Inspector countdown `setInterval` from `useEffect`** (Phase 0 §14.8 #5): same caveat — React 19 StrictMode double-mount leaks the interval in dev. Cleanup is wired; no production impact.
